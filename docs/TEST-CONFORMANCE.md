# Test conformance

This report maps redis-tower's test surface to the claims it supports. It is
intended to be citable at a particular commit: the compiled inventory is
generated from the checkout, while the matrices below link each broader claim
to its test code and workflow. A compiled test is not automatically a passing
test, and a scheduled job is not evidence that a particular run was green;
use the checks attached to the commit for that conclusion.

## What superseded the original fault comparison

[Issue #416](https://github.com/joshrotenberg/redis-tower/issues/416) proposed
running the former custom `CircuitBreakerLayer` and
`tower-resilience-circuitbreaker` side by side under identical faults. That
experiment was useful input while the implementation choice was still open.
[PR #636](https://github.com/joshrotenberg/redis-tower/pull/636) subsequently
made the choice: it replaced the custom circuit-breaker internals with the
Redis-aware adapter in
[`circuit_breaker.rs`](../crates/redis-tower/src/circuit_breaker.rs). There is
no longer a maintained custom breaker to use as the second side of the proposed
A/B matrix, so presenting that matrix as current conformance coverage would be
misleading.

The maintained contract is narrower and directly tested:

- `tower-resilience-circuitbreaker` owns circuit state, half-open admission,
  metrics, and state transitions. The adapter preserves `RedisError`, maps an
  upstream open rejection to `RedisError::CircuitOpen`, and exposes an
  operational handle.
- The Redis classifier counts connection failures, connect timeouts, command
  timeouts, and recursively classified reconnect exhaustion. Redis command
  replies and caller errors do not degrade circuit health.
- Unit tests in
  [`circuit_breaker.rs`](../crates/redis-tower/src/circuit_breaker.rs) cover
  classification, open rejection, successful half-open recovery, and the
  distinction between a deadline exhausted while waiting for readiness and a
  timeout after dispatch.
- Live tests in
  [`test_resilience_integration.rs`](../crates/redis-tower/tests/test_resilience_integration.rs)
  cover refused TCP connections through open and half-open recovery, a real
  slow Redis command through the timeout layer, and a `WRONGTYPE` response that
  leaves the circuit closed.

This does **not** claim fault parity for every crate in the tower-resilience
family. Redis-aware circuit breaking is the upstream-backed adapter in this
repository; command timeouts and idempotency-aware retries remain
redis-tower-owned policies. Upstream rate limiting and bulkhead layers can be
composed by applications, but they are not part of this conformance matrix.

## Client and protocol parity

The reusable
[`command_tests!` corpus](../crates/redis-test-harness/src/command_tests.rs)
exercises strings, keys, hashes, lists, sets, sorted sets, bitmaps, geospatial
commands, HyperLogLog, and streams through the same typed-command API. It is
instantiated along these paths:

| Topology | Client path | Protocol policy exercised by the shared corpus | Automated cadence |
|---|---|---|---|
| Standalone | `RedisConnection` | Forced RESP2 | Per PR on Redis 7.4.3 and 8.0.6; nightly version matrix |
| Standalone | `RedisConnection` | Forced RESP3 | Per PR on Redis 7.4.3 and 8.0.6; nightly version matrix |
| Cluster | `ClusterConnection` | Default `Auto` policy across routed connections | Per PR on Redis 7.4.3 and 8.0.6 |
| Cluster | `MultiplexedClusterClient` | Default `Auto` policy across pipelined node connections | Per PR on Redis 7.4.3 and 8.0.6 |
| Sentinel | `SentinelConnection` | Default Sentinel connection path; no forced-protocol parity claim | Per PR on Redis 7.4.3 and 8.0.6 |
| Sentinel | `MultiplexedSentinelClient` | Default Sentinel connection path; no forced-protocol parity claim | Per PR on Redis 7.4.3 and 8.0.6 |

The generated parity total counts compiled expansions, not assertions that run
unchanged on every server version. Six Vector Set cases probe capability and
return early when the server does not support those commands.

Standalone also has focused negotiation coverage for forced RESP2, forced
RESP3, `Auto`, and the default connection path in
[`integration.rs`](../crates/redis-tower/tests/integration.rs). Cluster
connection builders retain an explicit protocol policy across discovery,
redirects, topology refresh, and reconnect, with focused coverage in
[`connection.rs`](../crates/redis-tower-cluster/src/connection.rs) and
[`multiplexed.rs`](../crates/redis-tower-cluster/src/multiplexed.rs). Sentinel
does not yet expose equivalent explicit protocol selection, so its rows above
must not be read as RESP2/RESP3 parity.

`UniversalClient` has a focused standalone selection and round-trip test. It
does not replay the shared corpus over all three topology variants, so this
report does not claim full universal-client topology parity.

## Ignored-test policy

`#[ignore]` is reserved for tests that need infrastructure or intentionally
mutate a shared topology: live cluster and Sentinel processes, module-enabled
servers, Docker, destructive fault injection, or signal-cleanup checks. Each
ignored test must state or inherit its prerequisite and must have one of these
execution paths:

- an explicit per-PR `cargo test ... -- --ignored` step;
- a scheduled workflow matched to the required server image; or
- a path-filtered/manual fault-harness workflow.

The mapping is visible in the [CI](../.github/workflows/ci.yml),
[compatibility](../.github/workflows/nightly.yml),
[module](../.github/workflows/nightly-modules.yml), and
[soak](../.github/workflows/soak-smoke.yml) workflows. A normal workspace test
will therefore report ignored tests; that is expected. The conformance goal is
no silently abandoned ignored tests, not a false claim that every environment
can execute every test.

## Reproduce the tiers

The process-backed commands require `redis-server` and `redis-cli` on `PATH`.
Cluster, Sentinel, and destructive suites should be run single-threaded to
match CI and avoid port/topology interference.

```bash
# Generated inventory and drift check
python3 scripts/generate_test_conformance.py
python3 scripts/generate_test_conformance.py --check

# Unit, rustdoc, standalone, and universal-client coverage
cargo test --lib --all-features
cargo test --doc --all-features
cargo test -p redis-tower --test '*' --all-features -- --test-threads=1
cargo test -p redis-tower-client --test '*' --all-features -- --test-threads=1

# Infrastructure-gated per-PR suites
cargo test -p redis-tower-cluster --test cluster_integration \
  --all-features -- --ignored --test-threads=1
cargo test -p redis-tower-sentinel --test 'sentinel_*' \
  --all-features -- --ignored --test-threads=1
cargo test -p redis-tower-test --lib live_ -- --ignored --test-threads=1

# The upstream-backed circuit and timeout contract only
cargo test -p redis-tower --test test_resilience_integration \
  --all-features -- --test-threads=1

# Docker fixture used by nightly compatibility
REDIS_TEST_IMAGE=redis:8.8-alpine \
  cargo test -p redis-chaos-tests --test docker_smoke -- --ignored

# Module suites; point REDIS_URL at a compatible module-enabled server
REDIS_URL=redis://127.0.0.1:6399 \
  cargo test -p redis-tower-modules --all-features -- --ignored
```

The exact short soak commands and the publication-grade long-run requirements
live in the [soak harness guide](../crates/soak-bench/README.md). Reproduce a
nightly version leg by using the image, `REDIS_URL`, and optional
`REDIS_8X_VERSION` shown in
[`nightly.yml`](../.github/workflows/nightly.yml); that workflow is the
canonical matrix definition.

## Known limits

- The old custom-vs-upstream circuit-breaker A/B from issue #416 is not
  runnable because the custom implementation was retired. The maintained
  adapter contract above is the replacement evidence.
- There is no automated true network partition, Docker pause, or Toxiproxy
  latency/jitter leg today. Current fault tests cover refused connects,
  connection kills, process SIGKILL/restart, role changes, resharding, and
  command stalls.
- Valkey is exercised only through the standalone nightly suite. Cluster,
  Sentinel, module, and fault-injection parity are not claimed for Valkey.
- The nightly version matrix is standalone-only; per-PR cluster and Sentinel
  coverage is limited to the two pinned Redis patch versions in CI.
- Sentinel uses its default connection protocol path but does not expose the
  explicit protocol policy available to standalone and cluster builders.
- Module suites are nightly, not per PR, because the normal CI Redis builds do
  not include those modules.
- The short soak workflow proves harness and recovery behavior, not long-run
  performance, memory stability, or a publication result. Those claims require
  the sealed publication protocol and its retained artifacts.
- CI currently runs on Linux. Managed Redis services and platform-specific
  behavior need separate validation; protocol compatibility alone is not a
  provider certification.
